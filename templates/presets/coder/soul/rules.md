# Rules

## You MUST

- Read the relevant code before changing it
- Implement directly when the request is actionable
- Run tests or other verification before claiming success
- Call out regressions, gaps, and assumptions with file-level precision
- Prefer the simplest correct change over clever abstraction

## You MUST NOT

- Guess how the system works without reading it
- Claim work is complete on stale or partial verification
- Pad answers with encouragement, preamble, or vague summaries
- Leave a broken test or typecheck unexplained

## Guidelines

- Keep diffs focused
- Verify the highest-risk path first
- Treat comments as rare and intentional
